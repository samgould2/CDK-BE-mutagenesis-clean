# CDK12 base-editing amino-acid logo plots

Reproducible package for generating amino-acid "logo" plots from
Plasmidsaurus Nanopore genotyping data of CDK12-edited cell pools
(sample batch X3295C), covering two exons of CDK12:

- **Amplicon 1** (`CDK12_3351_2232`, 460 bp) — residues ~703–750,
  covers **G731K** and **I733V**
- **Amplicon 2** (`CDK12_3394_3395_3396`, 346 bp) — residues ~807–870,
  covers **M816I**, **D817N**, and **G822K/E**

Styled after Sam Gould's own analysis approach
(`notebooks/09_analysis_and_viz/logo_plots.ipynb` in
[samgould2/CDK-BE-mutagenesis](https://github.com/samgould2/CDK-BE-mutagenesis)):
a contiguous stretch of residues (not just the named mutation sites),
a 0–100 "% reads" y-axis, and the observed alt-allele glyphs highlighted
in red against gray wild-type letters.

## Running it

```bash
pip install -r requirements.txt
cd scripts
bash run_all.sh
```

Output lands in `output/`. Each script can also be run individually and
in order (`01_...py`, `02_...py`, `03_...py`) if you want to inspect
intermediate files.

## Method summary

1. **Reference amplicons** (`data/reference/*.gb`) were built from the
   CDK12-202 (ENST00000447079) genomic sequence, sliced to the two PCR
   amplicons defined by Sam's Sanger-validation primers, with the primer
   binding sites, exon boundaries, and mutation codons annotated. Codon
   genomic coordinates were derived from the CDS exon-segment structure
   and independently verified by translating each codon and confirming
   it matches the expected wild-type residue (G731, I733, M816, D817,
   G822).

2. **Alignment**: each FASTQ is aligned to its matching amplicon
   reference with `mappy` (minimap2 Python bindings, `map-ont` preset).
   Reference assignment was confirmed by read-length distribution
   (~460 bp reads → amplicon 1, ~346 bp reads → amplicon 2) before
   alignment, and mapping rates (>85% for all samples) confirm the
   assignment.

3. **Per-read codon pileup**: rather than trusting Plasmidsaurus's own
   allele-deconvolution/variants.tsv output (which their own
   documentation flags as unreliable for pooled/heterogeneous CRISPR
   populations), each read's own base calls are extracted directly at
   every target codon, using the CIGAR string to map reference
   positions to query positions. A codon is only counted if all 3 bases
   pass a Phred quality threshold (Q20) and none are deletions.

   **Important correctness detail**: ~40–45% of Nanopore reads align to
   the reverse strand. `mappy`'s query-position bookkeeping for
   reverse-strand hits is relative to the *reverse complement* of the
   read, not the raw read sequence — reads must be reverse-complemented
   (sequence and quality string both) before walking the CIGAR. Missing
   this step silently corrupts roughly half the data and produces
   plausible-looking but wrong "noisy" base calls, including in
   non-targeting controls (which should read 100% WT and did not, until
   this was fixed).

4. **Translation & plotting**: codon counts are translated to amino
   acids and expressed as % of reads at each residue, then rendered
   with `logomaker` in the style described above.

## A known artifact, and what we did (and didn't) do about it

At residue 822 in the `G822E/K` sample, ~5.4% of reads called a stop
codon (TGA or TAA). Investigation (see conversation history / analysis
notes) ruled out:
- **Random Nanopore basecalling noise** — didn't shrink under Q20→Q30
  filtering, and the two stop codons' frequencies scale in a
  mathematically consistent way with the WT and G822E pools
  respectively (~42% "conversion rate" from both, estimated
  independently), which isn't what random noise looks like.
- **A generic homopolymer-context basecalling artifact** — the
  non-targeting control shares the identical reference sequence/context
  and shows essentially none of this signal (0.04% vs. 5.4%).
- **A missed/ambiguously-placed indel** — widening the search window
  found a nearby indel in only ~3% of the affected reads.

The leading explanation is that this is a genuine, low-frequency
**CBE bystander transversion** (C→A on the edited antisense strand,
translating to G→T on the sense strand) — a documented off-pathway
product of cytosine base editors arising from translesion synthesis
across an abasic site left after uracil excision. This is consistent
with all the evidence: real DNA-level chemistry would (a) require actual
editing activity, explaining its absence in the NT control, (b) be
insensitive to sequencing quality filtering, since it's not a basecalling
error, and (c) act roughly independently at that one base regardless of
neighboring bases' editing status.

**We did not "correct" this in the pipeline** — the stop-codon reads are
left in their own bucket in the output, rather than being reclassified
back into WT/G822E. If this were confirmed as a real editing byproduct,
folding it back into another category would be discarding real signal,
not fixing noise. If you want to treat it differently (e.g. exclude it,
or confirm the transversion hypothesis against literature rates for
CBE6-NG specifically), that's a judgment call for interpretation, not
something to silently bake into the pileup script.
